# Permissions plugin `my-plugin` (commande `upload`)

Source : `tauri-docs/src/content/docs/develop/Plugins/index.mdx`, commit `ec113a50`, titre `Plugin Development` (sections `Command Permissions`, `Scope` / `Command Scope` / `Global Scope` / `Schema`, `Permission Sets`, `Default Permission`, `Autogenerated Permissions`).
Routage skill `tauri-plugin-dev` : intention « Écrire permissions » → `references/permissions.md` → exemples `examples/permission-allow-start-server.toml`, `examples/permission-scope-spawn-node.toml`, `examples/permission-set-websocket.toml`, `examples/permission-default.toml`, `examples/build-rs-autogen.rs` → validé par `scripts/check-plugin-dev.py --permission`.

> Par défaut les commandes ne sont pas accessibles au frontend (« By default your commands are not accessible by the frontend… To actually expose commands, you also need to define permissions that allow each command. »). Voir aussi « See the Permissions Overview documentation ».

## 1. allow / deny sur `upload` — `permissions/upload.toml`

```toml
"$schema" = "schemas/schema.json"

[[permission]]
identifier = "allow-upload"
description = "Enables the upload command."
commands.allow = ["upload"]

[[permission]]
identifier = "deny-upload"
description = "Denies the upload command."
commands.deny = ["upload"]
```

Règle doc : `identifier` suit la syntaxe identifiant (`references/plugin-basics.md`) ; `commands.allow` / `commands.deny` = listes snake_case (`upload`, comme `start_server` dans l'exemple doc), jamais de `plugin:` ici, jamais d'invention. Fichier livré : `permissions-upload.toml` (copie fidèle du gabarit `permissions/start-server.toml` transposé de `start_server` → `upload`).
Aucun identifiant inventé : `allow-upload`, `deny-upload`, `upload`, `my-plugin` seuls (tous `--identifier` OK).

## 2. Scope global — `permissions/spawn-node.toml` + `src/scope.rs` + `schemars` + `build.rs`

```toml
"$schema" = "schemas/schema.json"

[[permission]]
identifier = "allow-spawn-node"
description = "This scope permits spawning the `node` binary."

[[permission.scope.allow]]
binary = "node"
```

Règle doc : « When a permission does not define any commands to be allowed or denied, it's considered a scope permission and it should only define a global scope for your plugin. » Fichier livré : `permissions-scope-spawn-node.toml` (identique à `examples/permission-scope-spawn-node.toml`).

Struct scope (`src/scope.rs`, `schemars::JsonSchema` requis) — fichier livré `scope.rs` :

```rust
#[derive(Debug, schemars::JsonSchema)]
pub struct Entry {
    pub binary: String,
}
```

Dépendances (doc : « The scope entry requires the `schemars` dependency… `scope.rs` module is shared between the app code and build script ») :

```toml
[dependencies]
schemars = "0.8"

[build-dependencies]
schemars = "0.8"
```

Lecture côté Rust via `GlobalScope` (et `CommandScope` pour le scope par commande, `docs.rs` linkés, jamais copiés) ; doc : « We recommend checking both global and command scopes for flexibility ».

## 3. Set — `permissions/websocket.toml`

```toml
"$schema" = "schemas/schema.json"

[[set]]
identifier = "allow-websocket"
description = "Allows connecting and sending messages through a WebSocket"
permissions = ["allow-connect", "allow-send"]
```

Règle doc : « Permission sets are groups of individual permissions… » Fichier livré : `permissions-set-websocket.toml` (identique à `examples/permission-set-websocket.toml`).

## 4. Default — `permissions/default.toml`

```toml
"$schema" = "schemas/schema.json"

[default]
description = "Allows making HTTP requests"
permissions = ["allow-request"]
```

Règle doc : « The default permission is a special permission set with identifier `default`. It's recommended that you enable required commands by default. For instance the `http` plugin is useless without the `request` command allowed. » Fichier livré : `permissions-default.toml` (identique à `examples/permission-default.toml`).

## 5. Autogen `build.rs` — `COMMANDS = &["upload"]`

Fichier livré `build.rs` (combine autogen + scope schema, cf. `references/permissions.md` § Schema) :

```rust
#[path = "src/scope.rs"]
mod scope;

const COMMANDS: &[&str] = &["upload"];

fn main() {
    tauri_plugin::Builder::new(COMMANDS)
        .global_scope_schema(schemars::schema_for!(scope::Entry))
        .build();
}
```

Règle doc : « Inside the `COMMANDS` const, define the list of commands in snake_case (should match the command function name) and Tauri will automatically generate an `allow-$commandname` and a `deny-$commandname` permissions. » Ici `COMMANDS = &["upload"]` génère `allow-upload` / `deny-upload`. Cf. `examples/build-rs-autogen.rs`.

## Validation

```
python3 scripts/check-plugin-dev.py --permission permissions-upload.toml
# OK permissions-upload.toml: permissions fidèles (2 permission(s), 0 set(s))

python3 scripts/check-plugin-dev.py --permission permissions-scope-spawn-node.toml
# OK permissions fidèles (1 permission(s), 0 set(s))

python3 scripts/check-plugin-dev.py --permission permissions-set-websocket.toml
# OK permissions fidèles (0 permission(s), 1 set(s))

python3 scripts/check-plugin-dev.py --permission permissions-default.toml
# OK permissions fidèles (0 permission(s), 0 set(s), default)

python3 scripts/check-plugin-dev.py --identifier my-plugin
# OK identifier 'my-plugin' valide
# (idem allow-upload, deny-upload, allow-spawn-node, allow-websocket,
#  allow-connect, allow-send, allow-request, default, upload — tous OK)
```

## Frontière

La capability côté app (`capabilities/*.json`, `plugin:scope:cle`, fusion fenêtres, `deny` > `allow`, `trigger` exige `<plugin>:default`, CSP/asset-protocol) ne vit pas ici : seule autorité `tauri-security-capabilities`. Ici côté auteur uniquement (`permissions/*.toml` + `build.rs`), doctrine capability là-bas.
